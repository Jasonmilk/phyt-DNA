# SPEC · 知识本体
> 完整叙事。需要时才加载。

## 一 · 内核：生命线 + 不等式 + 容量

```
生 I1 有名 → applies-to + effective-from
活 I2 能红 → redtest（双轨心跳）
死 I3 会死 → revisit-on / expires-on
度 L 有度 → 三层注意力预算 ≤280 行
值 经济门槛 → f × C > 年维护成本
```

**不是四条并列原则，是一条生命线 + 一个容量。** I1→I2→I3 是真依赖。

## 二 · 唯一真源：闸门 = ADR 的一个属性

> **闸门池 = `decisions/` 中 `hard: true` 的 ADR 子集**

一个 `hard` 字段消灭整个独立闸门层：目录、生命周期、`supersedes` 全部复用。
`hard: false` = **失败案例索引**，年成本 ≈0。小坑收益 <20 分钟，用硬闸守是净亏损——
**它不是没长成的幼苗，是这类坑本就不该用树去挡。**

## 三 · 生长闭环

```
经历 → 记账(ledger) → 结晶(经济门槛+三要件) → 重放(注入) → 下一任务
                            ↓ 不达标
                      hard:false → 案例索引
```

年轮三数：`hits/任务` · `override_rate`（**按原因分类**）· `心跳红率 + 新增结晶数`

## 四 · 结晶投资阶梯

| C（单坑代价） | 第几次复发才结晶 |
|---|---|
| **不可逆 / 半天以上** | **第 1 次**（不等复发） |
| 1 小时级 | 第 2 次 |
| 30 分钟级 | 第 3 次 |
| **≤20 分钟** | 不配硬拦 → advisory |

⚠️ "第 2/3 次"是**组织规则**，非行业定律。渐进投资 vs 直接结晶：8h vs 42h/年。

## 五 · 验证栈（三层，各守一层）

```
L1 引擎    —— 验证代码（validate.sh，读 ADR 的 check 字段）
L2 spec-lint —— 验证闸门（闸门资产不得含静默失败/全量还原）
L3 CI      —— 验证一切（唯一真门禁，push 即触发）
```

**自指边界**：若一条规则的对象包含"验证它自己的工具"，
它不能是 probe 型硬闸门（无法检测自己的删除/污染），
必须降为 `hard: false`，由外部检测器承载。

## 六 · 三本账

| 账本 | 性质 | 说明 |
|---|---|---|
| `decisions/` | **冻结** | 改 = supersede，不改原文 |
| `ledger/` | **append-only** | 纠正 = 追加 `verdict: correction` |
| `INDEX/年轮/看板` | **派生** | 禁手编，只能脚本重生成 |

`appeals-<年>.jsonl` 独立申诉账 —— 破解"运营者自己分类自己"的自证陷阱。
