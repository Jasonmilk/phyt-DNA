# 诊断：`ADR-20261009-DNA-is-immutable` 基线恒红（只读诊断，**未改该 ADR**）

> 2026-10-09 ｜ 起因：`--probe-all` 修成"报两个世界"后，显出本仓唯一一条**基线红** ｜ **纯诊断**

## 现象

```
基线（未注入）: 红 → DNA 不可变: 禁止写入 DNA.md（改基因 = 修宪，走 ADR + 人批准）
```

## 三步取证（只读）

**① 读 `check` + `origin`：**

```yaml
applies-to: ["DNA.md"]
origin: "README 硬约束：DNA 不可直接编辑（改基因 = 修宪 = 走 ADR + 人批准）"
check: |
  [ "$F" = "DNA.md" ] && echo "DNA 不可变: 禁止写入 $F（改基因 = 修宪…）"
```

**② 手跑在 `DNA.md` 上：** 输出该消息（`exit=0`）。

**③ 命中的那一行是谁写的：**

```
DNA.md:2  > 本文件不可直接编辑。改基因 = 修宪 = 走 ADR + 人批准。
git log -1 -- DNA.md → ad9e1a7 refactor(v2): template/* 升至仓库根
```

## 结论：三种可能里的**第二种** —— `check` 表达式自命中

**该 `check` 断言的是「`$F` 这个字符串等于 `DNA.md`」。而 `applies-to: ["DNA.md"]` 使 `glob_first`
把它解析成 `DNA.md` ⇒ **条件恒真 ⇒ 恒红。****
**⇒ 它是一个**永远开火的守卫**：按 Ω，V = 0（永远为真的断言说明不了任何事）。**

**⇒ 而它真正要守的事（"DNA 没被改"）**已经由 `tools/check-baseline.sh` 的 sha256 在做**（CI 第 1 步）。

## 危害（比"误报"重）

**基线永远有一条红 ⇒ 噪音。** 而噪音**不是"多报了一条"**，是**它把真红挡住了** ——
2026-10-09 那次 `--probe-all`，注意力全被"三条假的不合规"占满，
**真正的基线红（就是这一条）反而没被注意**，直到把探针改成"报两个世界"才显出来。

## 修法（**已落地** —— 不是"建议"了，见下）

把 `check` 改成**能双向**的形式 —— 例如**与资产基线比对**：

```yaml
check: |
  base=$(grep -E '  DNA\.md$' tools/baseline.sha256 | awk '{print $1}')
  now=$(sha256sum DNA.md | awk '{print $1}')
  [ -n "$base" ] && [ "$base" != "$now" ] && echo "DNA.md 与资产基线不一致（改基因 = 修宪）"
```

**⇒ 这样它可以绿也可以红**（改了才红），**而不再恒红**。
**⇒ 实际采用的形态不是"改那个表达式"，而是把这条闸门改造成【元闸门】（P9 第一例）——
applies-to `tools/check-baseline.sh`，断言 `DNA.md` 在 `--scope` 的真实输出内（守"机制在位"，不守 DNA 内容）；
`DNA.md` 已纳入资产基线；判据从 scope 删掉 ⇒ 必须红（实测红了）。见 `decisions/ADR-20261009-DNA-is-immutable.md`。**

**（原分析保留如下，作为当时的推理：）**

1. 该文件在 `decisions/` ⇒ 改后须刷新 `tools/baseline.sha256`（本仓自定的规矩）
2. 它涉及 **DNA 的不可变性** ⇒ **改动本身就在"修宪"的边缘**
3. **故：只给建议，不擅动。**（本会话已发生过一次"差点为不存在的病去改权威卷"。）

## 也同步了：CI 与探针问的不是同一个问题

```
CI 步骤 1  check-baseline.sh      资产完整性
CI 步骤 2  spec-lint.sh           规范自检
CI 步骤 3  逐条 validate.sh --probe    ← 【能力】心跳：闸门会不会红
CI 步骤 4  validate.sh --timing post   全仓扫描
CI 步骤 5  spec-lint 必须可红
```

**⇒ CI 问「闸门会不会红」（能力）；探针的基线行问「仓库现在违规吗」（状态）。**
**⇒ CI 里**没有任何一步**检查"仓库当前是否合规"** ⇒ **一个仓库可以永远「CI 绿 + 实际违规」。**
**⇒ badge 不是装饰品**（它对它测的东西是诚实的），**但"仓库合规"这一格原本是空的** ——
**`--probe-all` 报"基线（未注入）"之后，它才第一次有了读数。**
