## 2 · 唯一真源：闸门不是新物件

> **闸门池 = `decisions/` 中 `hard: true` 的 ADR 子集**

一个 `hard` 字段消灭整个独立闸门层：独立目录（第二真源）、独立生命周期（复用 MADR 状态词）、出处字段（`supersedes` 自带）全部消失。

| 形态 | 是什么 | 年成本 |
|---|---|---|
| `hard: true` | **闸门**：进 INDEX、注入、拦截、有心跳、会死 | ≈60 分钟 |
| `hard: false` | **治理规则 / 失败案例索引**：不进 INDEX、不注入 | ≈0 |

> **advisory 不是"没长成大树的幼苗"，是这类坑本就不该用树去挡。**
> 小坑收益 <20 分钟，用 60 分钟/年的硬闸去守是净亏损。

**派生立法位阶**由此解决：DNA 派生区不是宪法的第二部分（那是绕过修宪的后门），而是 `decisions/` 的**投影，禁手编**。宪法不会被架空，因为派生区不独立承载内容。

## 3 · ADR 数据模型（可直接抄）

```yaml
---
id: ADR-20261009-PLAN-must-stay-under-150-lines   # 文件名 = id.md（唯一终身身份）
seq: 0001                                  # 仅 hard:true 且 accepted 才分配
status: accepted                           # proposed|accepted|deprecated|superseded
hard: true                                 # proposed 期必 false

# —— 生命 ——
applies-to: ["src/PLAN.md"]                # 生 · 空间边界
effective-from: 2026-10-09                 # 生 · 时间边界（缺它 ⇒ 追溯性误判）
timing: post                               # 生 · 时机（见 §4）
redtest: "validate --probe <id>"           # 活 · 双轨心跳
revisit-on: 2027-04-09                     # 死 · 续期批准 / 风险复审
expires-on: null                           # 死 · 自动删除（与 revisit-on 必填其一）

# —— 治理 ——
owner: "@someone"                          # 无所有者的行动项更不容易解决
origin: "ledger:e-9f2a / GROWTH#W41"       # 教训谱系（≠ supersedes 的闸门谱系）
risk: normal                               # high ⇒ 豁免频率冷存，走风险复审

# —— 判定逻辑（v2：数据驱动，引擎零硬编码）——
check: |
  [ -f "$F" ] || { echo "输入失效: $F 不存在（静默失败=伪证）"; }
  [ "$(wc -l < "$F")" -gt 150 ] && echo "$F $(wc -l < "$F") 行 > 150"

last-hit: null                             # 引擎回写，禁手编
hit-count: 0
supersedes: null
---
```

### check 字段（五个引擎 bug 逼出来的）

纯 bash 做**内容判定完全可行**（行数 / 条目数 / git diff）。
~~v5 说"v1 只能做路径黑名单"~~ **已被实测推翻**。真正做不了的是**语义判定**。

**三条铁律**：
1. **只用 `$F`**，不写死路径（否则重构后漏报）
2. **禁止 `2>/dev/null`**（静默失败 = 伪证）
3. 必须**显式校验输入有效性**

## 4 · timing：事前路径，事后内容（实测得出）

| timing | 判定方式 | 挂载点 |
|---|---|---|
| `pre` | **路径黑名单**（事前读不到未来内容） | PreToolUse |
| `post` | **内容判定**（行数 / 条目数 / git diff） | pre-commit / CI |

> **事后全仓扫描必须只跑 post 型**，否则 pre 型路径黑名单对每个文件都命中 ⇒ 必然误报。

这条修正了一个过头结论：**不是"内容判定优于路径黑名单"，而是两者服务不同时机。**

### 三个执行点（同一份引擎）

| 层 | 事件 | 机制 | 官方证实 |
|---|---|---|---|
| **注入** | UserPromptSubmit | `additionalContext`（官方 schema 字段） | ✅ |
| **拦截** | PreToolUse | **exit 2 + stderr**（唯一硬拦） | ✅ |
| **门禁** | CI | 非零退出（**唯一真门禁**） | ✅ |

> PreToolUse/PostToolUse 的 exit 0 stdout **通常只进调试日志**，不进上下文。
> **"注入与拦截挂不同事件"不是设计偏好，是官方机制决定的。**

`--no-verify` 官方证实可跳过 pre-commit ⇒ **本地提交层不是防线，CI 才是**。
原则从"不可绕过"改为"**绕过必留痕**"。

### 失败策略（spec-lint 强制守住）

| 场景 | 策略 |
|---|---|
| 权限 / 密钥 / 删除 / 公开契约 | **fail-closed** |
| 实验性建议 / 新闸门观察期 | **fail-open + 告警** |
| 引擎崩溃 / 超时 / 依赖缺失 | **fail-closed + 显式报警**（静默放行 = 伪证） |

## 5 · 验证栈（三层，各守一层）

```
L1 引擎 validate.sh   —— 验证代码（读 ADR 的 check 字段）
L2 spec-lint.sh       —— 验证闸门（静默失败 / 全量还原 / 字段缺失）
L3 CI phyt.yml        —— 验证一切（唯一真门禁，push 即触发）
```

### 自指边界（最深的一条）

> **若一条规则的对象包含"验证它自己的工具"，它不能是 probe 型硬闸门，
> 必须由外部检测器（spec-lint / CI）承载。**

三次实证：
1. **ADR-0007**（check 不得静默失败）：探针删它自己的文件 ⇒ 读不到 check ⇒ NOT RED
2. **ADR-0009**（测试不得破坏被测物）：fixture 污染真引擎 ⇒ 自污染循环
3. **spec-lint 自身**：grep 模式匹配到自己 ⇒ 扫描范围须排除自身

> **一个闸门不能在自己被删除后报告自己被删了。**
> **"别污染文件 X" 无法用"污染文件 X"来测试。**

## 7 · 生命周期：三种终点

| 终点 | 判据 | 字段 | 后果 |
|---|---|---|---|
| **① 自动删除** | 临时且机器可判定 | `expires-on` | 到期即失效 |
| **② 续期批准** | 长期仍有效（默认） | `revisit-on` | 到期需人重新批准 |
| **③ 风险复审** | 不可逆 / 高后果 | `risk: high` | **零触发不构成删除证据** |

> 英国政府 Sunsetting 指南明确区分日落条款与审查条款。
> **把三者都叫日落，会抹掉最重要的治理差别。**

### 冷存判据

```
可冷存 = (连续 N 个 kind:task 生产任务未命中) ∧ (能力心跳仍红)
豁免   = risk: high（仅受 revisit-on 复审约束）
```

**N = 20 必须落盘成 ADR（组织阈值 · 演算示例）。**
> **一条没有 id 的规矩，既无法被遵守，也无法被违反——它只能被遗忘。**

### 死亡证明（强制）

含：死者 / 出生 / 死亡 / 享年 / **引用判据** / 合规性审查 / 根因 / 处置。
> **不合规的退役若被写成成就，就是用伪证支撑结论** —— 这是 I2 红线。

## BACKFLOW 2026-10-09 · 第二根轴：判据的读数**可信吗**

本文件已要求判据**有名、能红**。"能红"保证**杀伤力**，**不**保证**读数可信** ——
缺后者时，一个"绿"可能是**未测量**，一个"红"可能是**噪声**。

```
verdict:  pass | block
validity: alive | unproven | unattributable | flaky
```

| 状态 | 判据 |
|---|---|
| `alive`（真绿的前提） | 该 gate **有夹具**且 `--probe` 证明**能红**；**正例 `inject.sh` 必须红，反例 `counter.sh` 必须不红** |
| `unproven` | **无夹具** ⇒ 从未被证明会红 ⇒ "通过"是**未测量** |
| `attributable`（真红的前提） | 红**且**理由就是这个判据（不是工具用法错、不是缺前置） |
| `flaky` | **同一命令两次不同答案** ⇒ 既非红也非绿，**不得作为证据** |

### 围栏（机械）

> **`pass` 单独不可报告 —— 必须是 `pass + alive`。**
> **"一组 gate 全绿而没有夹具" ⇒ 那不是绿，那是**未测量**。**
> （与既有的一条同源：**空集合上的"全部通过"是伪证** —— 见 `tools/validate.sh` 的零闸门 BLOCK。）

### 实现（三件，已在采用者 Cellrix 跑通，并在本仓 `--probe-all` 上验证）

1. **夹具**：`fixtures/<gate-id>/inject.sh`（正例）+ `counter.sh`（反例）
2. **探针留痕**：`--probe-all` 把结果写进 `ledger/`（`kind: probe`）
3. **账本行带两样**：`fingerprint` + `validity`（`gatesWithFixture` / `provenWithoutFixture` / `falseGreenRisk`）

### ★ 本仓第一次 `--probe-all` 的结果（2026-10-09）

**当时 6 个闸门全部活着（RED），但每个都报告"无反例夹具"** —— 即：**它们都只证了"该红的红"。**
**⇒ 现况（非当时）：闸门数 `ls decisions/ADR-*.md | wc -l` · 每个都已有反例（`counter.sh`）·
`bash tools/validate.sh --probe-all` 有"基线（未注入）/ 注入后 / 反例守住"三行。**
**⚠️ 本节初稿曾写成"三条闸门报出本仓自身的不合规"，那是**错读**，已更正：**
那三条 RED 是**夹具注入后**的世界（`PLAN.md 177>150` · `layer1 326>280` · `examples/phyt.yml` 残留），
**不是仓库的状态** —— 实测仓库为 `PLAN.md 26 行` · `DNA+RNA+SPEC 175 行` · `examples/phyt.yml` 无该残留。
**⇒ 教训：读探针输出必须确认"哪个世界"；只报注入态会把夹具的功劳当成仓库的病。**
**⇒ 已修 `tools/validate.sh`：每条先报【基线（未注入）】，再报【注入后】。**
**⇒ `--probe-all` 的真实价值不变：它让**一组**闸门同时被检查（此前只逐个跑）。**
