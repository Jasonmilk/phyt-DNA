# 发现 2026-10-09：账本不是 JSONL —— 而"按行读"的消费者全都读错

## 事实（工具自己量出来的，不是估的）

```
wc -l              ledger/hits-2026.jsonl   ⇒ 334 行
按行 json.loads    ⇒ 258 行可解析 · 76 行不可解析
整份文件当【流】解析 ⇒ 1069 条记录
```

**334 行装不下 1069 条，除非**记录之间没有换行**。⇒ 该文件是**拼接的 JSON 流**，
不是 **JSON Lines**（JSONL 的定义就是**一行一条**）。⇒ 任何按行读的消费者都会读错：
`grep -c`、闸门引擎、`tools/claim-check.sh`、以及任何外部脚本。

## 为什么这要紧

* **本仓的 SSOT 就是账本。** 如果它按行读不了，那么"每次判定留痕"的**读取**这一半是断的 ——
  证据写进去了，**但读者读不明白**，等于没有。
* `kind:task` 行实测 **0 条** ⇒ "只算 `kind: task` 进生产指标"**没有承载体**。
* 现有闸门 `ADR-20261009-ledger-must-be-valid-utf8` **只查编码**，而它的注释写着
  *"否则读者无法解析该行"* —— **意图是"解析"，检查只到"编码"**。
  ⇒ **这正是"声明代替检查"，长在本仓自己的闸门里。**
* 申诉账**有**解析闸门（`applies-to: ledger/appeals-2026.jsonl`），主账**没有** ⇒ **同类两治**，
  而被漏掉的那个更要紧。

## 与"agent 通病"的关系（人类 2026-10-09 提问）

人类问：**你会看吗？看了会记得吗？记得了会执行吗？**
本轮我给出三个自己的标本：
1. 凭记忆写 `tuck-audit::append` 的签名 ⇒ **错**（真签名是 `append(&dyn Clock, serde_json::Value)`）。
2. 凭记忆写**我自己刚写的** `"bypass"` 表达式形状 ⇒ 正则 **0 匹配**，替换落空而插入生效 ⇒
   **净 +5 行，把红弄得更红**。★ 而脚本**当场打印了「压掉 0 处重复」** —— 检查跑了、数据在、
   **流程没停**。
3. 报告"全绿"却**没跑那个仓自己的闸门**（行预算是个测试）⇒ **声明的边界没覆盖正在改的仓。**

**⇒ 结论：这三个问题都不能靠"我自觉"解决。** 机制必须让三件事**不依赖我**：
**"我会看" → 文件逼我看（机械检查）· "我会记得" → 账本替我记 · "我会执行" → 0 就 FAIL、流程停。**
